# Жизненный цикл и перерождение сущностей

## 1. Принцип

Жизненный цикл — это не поле объекта, а управляемая последовательность состояний и событий.

## 2. Базовые состояния

| Состояние | Значение |
|---|---|
| `draft` | Черновик, не подтверждён |
| `candidate` | Кандидат на включение |
| `active` | Действующая версия |
| `superseded` | Замещена новой версией |
| `rejected` | Отклонена |
| `archived` | Архивная, неактивная |

## 3. Перерождение

Перерождение — переход сущности в новое поколение с сохранением идентичности.

```text
wall-123@gen:2  →  wall-123@gen:3
```

При перерождении сохраняются:

- `av_id`;
- история;
- провенанс;
- связь с физическим объектом;
- ссылка на предшественника.

## 4. Причины перерождения

- Изменение по нормативному требованию.
- Прямое изменение человеком.
- Обновление источника IFC5.
- Исправление ошибки.
- Смена роли или представления.
- Реструктуризация модели.

## 5. Событие жизненного цикла

```json
{
  "event_id": "lc-000123",
  "entity_ref": "wall-123@gen:3",
  "event_type": "rebirth",
  "reason": "normative_change",
  "rule_ref": "NORM-001",
  "snapshot_ref": "snap-001",
  "evidence_ids": ["ev-118"],
  "decision_id": "dec-207",
  "actor": "human:kirill"
}
```

## 6. Правила

1. Существенное изменение создаёт новое поколение.
2. Прежнее поколение получает `superseded`.
3. История не удаляется.
4. Нормативное изменение требует ссылки на правило и доказательство.
5. Человеческое изменение требует решения и автора.
6. Каскады не изменяют snapshot.
